## Executive Summary

These six documents are not malformed customer-receivable documents.

They are posted purchase invoices generated by `AccountingPostingService::fromInvoice()` from confirmed purchase invoices:

- `PI-00005`
- `PI-00006`
- `PI-00007`
- `PI-00008`
- `PI-00009`
- `PI-00010`

Each document carries the expected supplier-side structure:

- debit `5201` `هزینه عمومی` with description `هزینه خدمات`
- credit `2101` `حساب‌های پرداختنی تجاری` with the same party

That means the documents are legitimate supplier-side expense documents, not accidental customer receivable postings.

The statement-balance issue is therefore a party-data / business-partner-design issue, not a posted-document corruption issue.

## Correction Plan

Because these are legitimate purchase invoices, the safest plan is:

1. Do not mutate the six posted accounting documents.
2. Do not reverse them unless the underlying purchase invoices themselves were wrong.
3. Do not delete or unpost them.
4. If the business rule is that `محسن اخلاصی` and `حمید علیزاده` should be customer-only parties, introduce separate supplier-side party records in a future data-cleanup process and reassign future purchase invoices to those supplier records.
5. If the supplier/customer split is already intentional, then no correction is needed for these documents.

## Source Of The Balance Distortion

The distortion is not in the posted-document structure.

It comes from reusing the same `party_id` on supplier-side purchase invoices. That is valid accounting behavior if the party is meant to represent the same business partner across customer and supplier activity. It becomes a business-design problem only if the ERP intends separate party identities for receivable and payable relationships.

## Code Bug Assessment

No application-code bug is demonstrated by these six documents alone.

The documents match the normal purchase-invoice posting path in `AccountingPostingService::fromInvoice()`:

- expense side: `5201`
- payable side: `2101`
- same `party_id`
- posted status

So this is a live data / party-model correction question, not a posted-document correction question.
