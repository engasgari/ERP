# 19 — CRM AI (Phase 0 infrastructure + Phase 1 Customer Intelligence + Phase 2 Sales Task Planner)

## Pipeline

CRM Database → Laravel rules (scope, allowlist, candidate selection) → AI analysis → structured output →
Laravel validation + source rules → human review → (future) CRM action → feedback.

Hard rules:

- The model never touches the database, never produces SQL and never writes CRM data.
- Laravel selects data, applies user scope (`CrmCustomerRepository::findForShow`) and the per-agent field allowlist.
- Output must pass `AiOutputValidator` (Laravel validation rules from the prompt definition). Invalid output is never stored as a result.
- AI results are suggestions with `review_status = pending_review`; accept/reject is recorded, nothing is applied automatically.
- Amounts and dates shown to users come from Laravel queries (`CrmCustomerInsightService`), never from AI text.

## SDK status (important)

`laravel/ai` is **not installed**. Every 1.x release requires `illuminate/json-schema ^12.62`, i.e. `laravel/framework >= 12.62`;
the project is on 12.33.0. `composer require laravel/ai` (dry-run) would upgrade the framework to 12.69 and ~60 dependencies
(Symfony 7.3 → 7.4/8.1). That upgrade needs explicit approval and a full regression run.

Until then the provider boundary is the `App\Services\Ai\Contracts\AiGateway` interface:

| driver (`CRM_AI_DRIVER`) | class | behaviour |
|---|---|---|
| `null` (default) | `NullAiGateway` | every call fails with `not_configured`; nothing is sent anywhere |
| `fake` | `FakeAiGateway` | deterministic, for tests/demos; never contacts a provider |
| `openai` | `OpenAiCompatibleGateway` | `POST {base_url}/chat/completions` with `response_format` json_schema (or json_object); key from `CRM_AI_API_KEY`; HTTP 401/403 → `not_configured`, 429 → `provider_rate_limited`, 5xx/timeout → retryable |
| `laravel_ai` (future) | adapter over the real SDK | to be written against the installed SDK version, not guessed |

Real OpenAI calls have **not** been executed or verified. Tests use the fake gateway only.

## Statuses

- Technical run (`ai_runs.status`): `pending`, `running`, `completed`, `failed`, `cancelled` (feature disabled / expired).
- Business result (`crm_customer_intelligence.status`): `pending`, `completed` (identity matched with verified sources),
  `insufficient_data` (ambiguous / not found / no sources), `failed`.
- Human review (`review_status`): `pending_review`, `accepted`, `rejected` (`expired`, `applied` reserved for later phases).

Error codes (`AiException`): `disabled`, `not_configured`, `unauthorized`, `rate_limited`, `budget_exceeded`, `cost_unknown`,
`duplicate_request`, `input_too_large`, `invalid_input`, `timeout`, `provider_rate_limited`, `provider_error`, `invalid_output`.
Only `timeout`, `provider_rate_limited`, `provider_error` are retried (bounded, exponential backoff, inside `AiRunner`).
The queued job has `tries = 1` and `ShouldBeUnique`, so queue retries cannot create duplicate results or duplicate charges.

## Cost control

- Monthly ceiling `CRM_AI_MONTHLY_BUDGET_USD` (0 = off). Spend = sum of reported cost, else estimated cost, this month.
- Estimated cost is computed only when `crm_ai.budget.pricing[model]` is configured; otherwise `cost_status = unknown`
  and the cost is stored as NULL (never a made-up number).
- With a ceiling set and unknown pricing, new runs are blocked unless `CRM_AI_ALLOW_UNKNOWN_COST=true`.
- Rate limits per user/agent per hour via Laravel `RateLimiter`.

## Privacy

- Only allowlisted paths (`crm_ai.payload_allowlist.customer_intelligence`) leave the system.
- Free text is masked (mobile/landline numbers, 10+ digit identifiers, e-mail, IBAN, card numbers) before sending and before logging.
- Personal national codes are never sent; company registration number / national ID (public company identifiers) are sent only for `kind = company`.
- CRM facts sent to the model contain counts, dates and statuses only — no amounts, contact people or phone numbers.
- Activity subjects are sent as `subject_untrusted`; the prompt treats all input, CRM text and web pages as data, not instructions.
- `ai_runs.input_payload/output_payload` store the sanitized, masked, length-limited JSON (`CRM_AI_LOG_PAYLOADS=false` disables).
  They are hidden from model serialization. `crm.ai.runs.view` permission is reserved for a future log viewer.
- Not decided here (needs the business owner): user/customer consent, provider data-processing terms, retention period for `ai_runs`.

## Source rules (Customer Intelligence)

- A source is verified only if `VerifiedSourceFetcher` downloaded it (HTTP 2xx, HTML/text, public host, no redirect followed).
- Every URL in the model output that is not one of the fetched verified URLs is dropped. Claims tied to unknown URLs are dropped.
- `official_website` is kept only if its host matches a verified source.
- If identity is not `matched` or no valid source remains, all external profile fields are cleared and the reason is recorded in `missing_information`.
- With no search provider configured, the result honestly states that the web was not checked.

## Freshness

`fresh_days` / `review_days` (config) classify a summary as تازه / نیازمند بازبینی / قدیمی. Only manual refresh exists in Phase 1;
scheduled and change-triggered refresh are future work.

## Deployment notes

- Run `php artisan migrate` (adds `ai_runs`, `crm_customer_intelligence`, `crm_customer_intelligence_sources`, AI permissions).
- A queue worker is required (`QUEUE_CONNECTION=database`): e.g. `php artisan queue:work --queue=default --tries=1 --timeout=300`.
  `docker-compose.yml` currently has no worker service; without a worker requests stay pending and expire after `CRM_AI_LOCK_SECONDS`.
- OpenAI reachability from the production server (direct or via gateway/proxy) is unverified.

## Phase 2 — Sales Task Planner

Pipeline: Laravel candidate selection (scoped) → AI rank/draft → validate → human accept/reject → `CrmTaskService::create` (or reschedule overdue task).

Candidate kinds (deterministic): `new_lead_no_contact`, `opportunity_idle`, `proforma_idle`, `overdue_task`,
`dormant_customer`, `high_value_opportunity`, `near_close_opportunity`. Amounts leave the system only as `amount_tier`
(high/medium/low/none), never as raw money.

Accept creates a real CRM task; reject only records the decision. AI never writes tasks or changes opportunity status by itself.

Permissions: `crm.ai.sales_task_planner.request`, `crm.ai.sales_task_planner.apply` (apply also needs `crm.tasks.create`).
Flag: `CRM_AI_SALES_TASK_PLANNER_ENABLED`.
